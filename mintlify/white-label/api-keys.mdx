A platform key lets your own code create businesses and set them up through LobbyStack's [API](/api/overview). It also lets the `lobbystack onboard` command build a business from one file. Owners and admins make keys on the console's **API keys** page. A key acts as your partner and reaches only your businesses.

## Create a platform key

Give each tool its own key, so you can revoke one without breaking the others:

<Steps>
  <Step title="Open the form">
    On **API keys**, click **Create API key**.
  </Step>
  <Step title="Name the key and pick its access">
    Enter a **Name** you'll recognize, such as `Client onboarding`. Under **Access**, select only what the tool needs. To create businesses, select **Create businesses and invite their owners**. To run your partner from code, select the partner access the tool needs. Only owners see the billing access.
  </Step>
  <Step title="Copy the key">
    Click **Create key**, then copy the key and store it in a password manager or your tool's settings. The console shows it once.
  </Step>
</Steps>

The page lists each key by name, with who created it and when, and when it was last used. Members see the page but can't make, update or revoke keys.

## What a partner's key can do

A partner's key acts as your partner rather than as a person, so it keeps working when the teammate who made it leaves. It reaches your active businesses, including the ones the console created, and no others:

- `POST /businesses` creates a business with no owner yet. Name the owner in `owner_email`, and LobbyStack emails them your invitation. `access_level` takes `full`, the default, or `activity`.
- Every other request names its business in the `LobbyStack-Business` header.
- Links the API returns, such as a widget's script tag or a calendar connect link, point at your address.

Your keys can create 30 businesses an hour between them. `POST /businesses` takes `template_id` to start from one of your templates, which needs `partner:read`, and `package_id` to sell one of your packages, which needs `partner.businesses:write`. A key can't search for or claim phone numbers, or change alert preferences, so do those in the console.

[Platform keys](/api/authentication#platform-keys) lists the scopes, headers and responses.

## Run your partner from code

With the partner access, a key does what the console does. It makes and publishes demos, manages packages, changes your brand and domain, saves templates, invites your team, releases or deletes businesses, and shows your tier and Stripe account. A coding assistant or your own scripts can then do your White Label work through the API or the `lobbystack` command:

```bash
lobbystack demos create "Harbor Dental" https://harbordental.example
lobbystack packages list
lobbystack partner-team invite sam@youragency.example member
```

The key acts as an admin, so it can't invite an owner or change an owner's role. Only owners can give a key billing access, and a tier checkout the key starts goes to the owner who gave it that access, when they created or last updated the key. Billing access lasts while that person is still an owner. If they become an admin or leave your team, the key loses billing access and keeps the rest. Write access to billing includes read access. [Partner endpoints](/api/authentication#partner-endpoints) lists what each access allows.

## Onboard a business from a file

`lobbystack onboard` reads a YAML or JSON file that describes a business, creates the business and sets it up. Sign in with your partner's key first. On LobbyStack's cloud, use `https://app.lobbystack.com`:

```bash
lobbystack login --url https://app.lobbystack.com --key-stdin < key.txt
```

The key needs `businesses:create`, `business:read`, `business:write`, `knowledge:read`, `knowledge:write` and `team:manage`. A manifest for a partner's key names the owner, who gets your invitation when the command creates the business:

```yaml harbor-dental.yaml
business:
  name: Harbor Dental
  timezone: America/Toronto
  access_level: activity
knowledge:
  websites: [https://harbordental.example]
receptionist:
  greeting: Thanks for calling Harbor Dental, how can I help?
owner:
  email: owner@harbordental.example
```

Leave `plan` and `phone_number` out: your businesses don't buy LobbyStack's plans, and a key can't claim numbers. Preview the run with `--plan`, then run it:

```bash
lobbystack onboard harbor-dental.yaml --plan
lobbystack onboard harbor-dental.yaml
```

Run the command again whenever the file changes, and it changes only what differs. Your key keeps reaching the business after its owner joins. [Onboard a business from the command line](/api/cli) covers every section of the file.

## Update a key

Click **Update** beside the key to change its name or access, then **Save**. The key stays the same, so your tools keep working with it and get the new access on their next request. You can't update a revoked key.

Only owners can update a key that has billing access, so admins see **Update** turned off on those keys. An owner who saves a key with billing access becomes the owner that access depends on.

## Revoke a key

Click **Revoke** beside the key, then **Revoke key**. Anything that uses it stops working right away, and you can't undo it:

- the webhook endpoints the key created turn off, on every business
- nobody can accept the invitations it sent, to a business's team or to yours
- owners it invited when it created their business can still join
