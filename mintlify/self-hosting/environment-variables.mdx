Use `.env.example` as the source of truth. Store production values in your deployment secret manager or a permission-restricted `.env` file.

## Application and database

| Variable | Purpose |
| --- | --- |
| `APP_BASE_URL` | Public HTTPS URL for the dashboard and API. |
| `DEPLOYMENT_MODE` | `cloud`, `self_hosted_standard`, or `development`. |
| `DATABASE_URL` | PostgreSQL connection for the service's main role: `lobbystack_app` for the admin, `lobbystack_worker` for the worker. |
| `LOBBYSTACK_AUTH_PASSWORD`, `LOBBYSTACK_WORKER_PASSWORD`, `LOBBYSTACK_DISPATCHER_PASSWORD` | Passwords for the other roles. A service connects as each role by combining `DATABASE_URL`'s host and database with that role's password. |
| `LOBBYSTACK_<ROLE>_DATABASE_URL` | Optional. Overrides the built connection string for one role, for example to use a different host. |
| `BETTER_AUTH_SECRET` | Better Auth signing secret. Use at least 32 random characters. |
| `ENCRYPTION_KEY` | Encrypts stored application credentials. |
| `OTP_HASH_SECRET` | Hashes one-time verification codes and callers' keypad PINs. Set the same value on the admin and the worker. Changing it makes every saved PIN stop working. |

## Branding

Set these on the admin. Each one wins over the name and logo that the deployment's first owner chooses during onboarding, so leave them empty to let that owner choose. Give them to the admin build as well, as Docker build arguments with the same names, so the prerendered sign-in pages show them without first asking the server.

| Variable | Purpose |
| --- | --- |
| `BRAND_APP_NAME` | The name the dashboard shows instead of LobbyStack, up to 40 characters. It appears in the browser tab, above the sign-in and onboarding pages, and in dashboard text. |
| `BRAND_LOGO_URL` | The logo shown beside the name and as the browser tab icon. Use an `https://` URL or a path on the dashboard, such as `/brand/logo.svg`. Without a logo, a renamed deployment shows its name on its own. |

The dashboard's links to pages outside it come from five more variables. Next.js writes them into the admin build, so pass them as Docker build arguments with the same names, and rebuild after changing one. Leave one unset or empty to link to LobbyStack's page.

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_LANDING_SITE_URL` | Your website, such as `https://example.com`. The public demo page links to it, and the SMS HELP reply gives it. Without their own variables, the terms and privacy links open `/terms` and `/privacy` there. |
| `NEXT_PUBLIC_TERMS_URL` | Your terms of service, linked under the sign-up form, at the foot of onboarding, and from the affiliate program. |
| `NEXT_PUBLIC_PRIVACY_URL` | Your privacy policy, linked under the sign-up form and at the foot of onboarding. |
| `NEXT_PUBLIC_DOCS_SITE_URL` | Your docs, linked from the dashboard's feedback panel and the MCP server's metadata. |
| `NEXT_PUBLIC_CONTACT_EMAIL` | The one address people write to: the feedback panel's contact link, the Enterprise plan's contact button, and the SMS HELP replies. |

The SMS HELP reply opens with the app name. Emails, the API, and other text messages still say LobbyStack.

## Internal services

| Variable | Purpose |
| --- | --- |
| `INTERNAL_SERVICE_SECRET` | Signs browser call end tokens and other short-lived internal values. |
| `INTERNAL_SERVICE_TOKEN` | Authenticates the admin's call handoff to the worker and protected internal health routes. Set the same value on admin and worker. |
| `WORKER_INTERNAL_URL` | Private URL of the worker's HTTP port, used by the admin to hand each call to the worker. Compose sets this to `http://worker:3002`. |

## Voice calls

OpenAI's GPT-Live model answers browser calls and phone calls. Phone calls reach it through your Twilio SIP trunk. The admin starts each call and the worker runs it.

| Variable | Purpose |
| --- | --- |
| `LIVE_PROTOTYPE_ENABLED` | Set to `true` on admin and worker. Compose sets it by default. Browser calls fail without it. |
| `OPENAI_WEBHOOK_SECRET` | Verifies OpenAI's incoming-call webhook at `/api/webhooks/openai/live`. Phone calls only. |
| `TWILIO_SIP_TRUNK_SID` | The Twilio Elastic SIP trunk that sends calls to your OpenAI project. New numbers join it, and the worker won't provision a number without it. |
| `WEB_CALL_MAX_DURATION_MS` | Optional cap on browser call length. |
| `WEB_CALL_PUBLIC_BUSINESS_SLUG` | Business that answers the public demo call on your marketing site. |
| `WEB_CALL_ALLOWED_ORIGINS` | Comma-separated sites allowed to start that public demo call. Website widget calls use each widget key's allowed origins instead. |

## Redis and file storage

| Variable | Purpose |
| --- | --- |
| `REDIS_URL` | Redis connection URL used by admin and worker runtimes. |
| `STORAGE_PROVIDER` | `local` by default. Set to `s3` for AWS S3, MinIO, or another compatible service. |
| `LOCAL_STORAGE_PATH` | Filesystem path shared by the admin and worker. Compose mounts its persistent volume at `/var/lib/lobbystack/storage`. |
| `LOCAL_STORAGE_SIGNING_SECRET` | Signs short-lived local upload and download URLs. Use a long random value. Falls back to `INTERNAL_SERVICE_SECRET` outside Compose. |
| `S3_ENDPOINT` | Optional S3-compatible endpoint. Leave empty for AWS S3. |
| `S3_BUCKET` | Bucket for recordings and uploads. |
| `S3_REGION` | S3 region. Defaults to `us-east-1`. |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Object-storage credentials. |
| `S3_FORCE_PATH_STYLE` | Set to `true` for MinIO. |

Local storage fits a single-host deployment. Use S3 when the admin and worker run on different hosts or when you need storage managed outside the Docker host.

## Public API and webhooks

| Variable | Purpose |
| --- | --- |
| `PUBLIC_API_RATE_LIMIT_PER_MINUTE` | Requests per minute for each API key on `/api/v1`. Defaults to `120`. Set it on the admin. The limit uses `REDIS_URL`; in production, requests fail with `503` when Redis is unreachable. |
| `PLATFORM_API_KEYS` | Platform keys (`lsp_...`) that onboard and manage businesses on `/api/v1`, as a JSON array. Each entry names its group (`group`), the verified account it acts as (`owner_email`), and whether it can reach every business (`"access": "all"`) or only the ones its group's keys onboarded (`"access": "group"`). Older entries name the group in `partner`, which still works. `pnpm platform-key:create` makes a key and prints its entry; the entry stores only a hash of the key. A key with `"access": "all"` and its owner account are root credentials: they reach every business. Set it on the admin. Leave it empty for none. The keys partners make in their consoles live in the database instead. |
| `ENCRYPTION_KEY` | Also encrypts webhook signing secrets and keys the HMAC that stores API key hashes. Set the same value on the admin and the worker, or the worker can't sign deliveries. Changing it invalidates every API key and webhook secret. |

Webhook deliveries refuse private, loopback, link-local and cloud metadata addresses on every deployment, including self-hosted ones. Point endpoints at a public HTTPS URL. Plain `http://` URLs work only when `NODE_ENV=development`.

## Partners

Partners resell your deployment to the businesses they serve, under their own brand. They sign up and run their team from the partner console at `/partner` on your dashboard. Set these on the admin and the worker.

| Variable | Purpose |
| --- | --- |
| `PARTNER_SIGNUP` | Who can sign up as a partner at `/partner/signup`: `open` lets anyone, and `invite` needs a signup link. `pnpm partner-invite:create --email owner@acme.example` writes a link that works once, for that verified email, for 7 days. Defaults to `open`, except when `DEPLOYMENT_MODE` is `cloud` and partner tier billing is off: then it defaults to `invite`, so no partner signs up before it can buy a tier. Partner tier billing turns on once every `POLAR_PARTNER_*_PRODUCT_ID` is set. |
| `PARTNER_BASE_DOMAIN` | The domain your partners get subdomains of, such as `receptionistportal.com`. Signup reserves one for each new partner, such as `acme.receptionistportal.com`, and the admin reserves one when it starts for each partner that signed up before you set it. People sign up and sign in on those subdomains under the partner's brand, with email and password. A partner's own emails, such as invitations to its team, go out under its name from `no-reply@` that domain, so your email provider must accept that sender. Without this variable, a partner's emails go out from the address in `EMAIL_FROM`. Replies go to the support email the partner sets on its **Branding & domain** page. |
| `STRIPE_CONNECT_SECRET_KEY` | A secret key (`sk_...`) or a restricted key (`rk_...`) of your Stripe platform account, with write access to Connect accounts, products, prices, Checkout Sessions, customer portal sessions, subscriptions, subscription items, billing meters and meter events. Turn on Connect in your Stripe account first, and set both Stripe Connect variables on the admin and the worker. With `STRIPE_CONNECT_WEBHOOK_SECRET`, this key turns on Stripe Connect. Each partner's owner then connects the partner's own Stripe account on the console's **Payments** page. Owners and admins sell packages on the **Packages** page and pick each business's package on the **Businesses** page. There they can also turn on a business's overage, with a price for each extra minute and each extra chat and an optional monthly cap, in the package's currency. The business then keeps answering past its package's minutes and chats until its overage reaches the cap. With overage off or at the cap, its calls forward and its website chat stops replying. The worker sends each business's overage to the partner's Stripe account as meter events, one per call or chat, and adds Call overage and Chat overage prices to the business's subscription the first time it has some, so the overage shows on the business's next invoice. The business's owners and admins get an email under the partner's name at 80% and at 100% of its package's minutes and of its chats. The business's owner pays at a Stripe Checkout on the partner's account, which the invitation link opens. Later, the owner opens the partner's customer portal from **Settings → Billing**, so each partner saves its customer portal settings in its own Stripe Dashboard. Ninety days after a partner's tier ends, the worker deletes the partner's businesses and first cancels each one's package subscription, so its owner pays nothing more. Without both variables, partners bill every business outside LobbyStack. |
| `STRIPE_CONNECT_WEBHOOK_SECRET` | The signing secret (`whsec_...`) of the webhook endpoint at `APP_BASE_URL` + `/api/webhooks/stripe`. In Stripe, create the endpoint for events on connected accounts, and send it `account.updated`, `account.application.deauthorized`, `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `customer.subscription.paused`, `customer.subscription.resumed`, `invoice.paid` and `invoice.payment_failed`. The console then shows when a partner's account can take payments, and when the partner disconnects it. A business on a package gets its minutes and chats while its subscription pays, past due included. |
| `POLAR_PARTNER_STARTER_MONTHLY_PRODUCT_ID`, `POLAR_PARTNER_STARTER_ANNUAL_PRODUCT_ID`, `POLAR_PARTNER_GROWTH_MONTHLY_PRODUCT_ID`, `POLAR_PARTNER_GROWTH_ANNUAL_PRODUCT_ID`, `POLAR_PARTNER_SCALE_MONTHLY_PRODUCT_ID`, `POLAR_PARTNER_SCALE_ANNUAL_PRODUCT_ID` | The Polar products you sell partner tiers with: Starter, Growth and Scale, monthly and annual. When all six are set, each to its own product, a partner's owners buy a tier from the console's **Billing** page and pay at a Polar checkout. Polar's webhooks then set the partner's tier through the same `POLAR_WEBHOOK_SECRET` as your plans. A partner that pays for no tier is on Free. When a partner's paid tier ends or a payment fails, its businesses keep answering for 30 days. Then they pause and their calls forward, and 90 days after the tier ended, the worker deletes them and releases their phone numbers. A tier also sets how many phone numbers the partner's businesses hold, and each extra number costs the partner what Twilio charges you for it. The tier's pool limits the minutes and chats the partner's businesses share each month. Past the pool they keep answering, and the worker sends the overage to Polar as `billing.partner_pool_voice_overage` and `billing.partner_pool_chat_overage` events, up to the monthly cap the partner's owners set. The partner's owners and admins get an email at 80% and at 100% of the pool and of the cap. Free has no overage. Leave them empty and partners pay you no tier. Nothing then limits the phone numbers their businesses use, or their minutes and chats unless you set a partner's pool, as the next section describes. The **Billing** page shows the cloud's prices, so give your products the same ones. They need `POLAR_ACCESS_TOKEN` and `POLAR_ORGANIZATION_ID` too. |
| `CADDY_ON_DEMAND_TLS` | Set to `true` when Compose's Caddy serves HTTPS through `docker-compose.tls.yml`. Partners can then connect a subdomain of their own website, such as `app.acmeagency.com`, on the console's **Branding & domain** page. While you sell partner tiers through the `POLAR_PARTNER_*` products, a partner needs a paid tier for it; otherwise any partner can. The worker checks every few minutes that the domain's DNS reaches `PARTNER_DOMAIN_CNAME_TARGET` and holds the partner's TXT record, and the domain goes live once it does. Caddy issues its certificate on the first visit, after `/api/tls/ask` approves it. Defaults to `false`. |
| `CLOUDFLARE_SAAS_API_TOKEN` | A Cloudflare API token with permission to edit custom hostnames in the zone of `CLOUDFLARE_SAAS_ZONE_ID`. With both set, partners connect their own domains through Cloudflare for SaaS instead of Caddy: the worker registers each domain as a custom hostname, and the domain goes live once Cloudflare reports the hostname and its certificate active. |
| `CLOUDFLARE_SAAS_ZONE_ID` | The ID of the Cloudflare zone that holds your custom hostnames, usually the zone of `PARTNER_BASE_DOMAIN`. Give the zone a fallback origin that reaches your admin. |
| `PARTNER_DOMAIN_CNAME_TARGET` | The hostname partners point their domain's CNAME record at. Defaults to the zone's fallback origin with Cloudflare for SaaS, and to the hostname in `APP_BASE_URL` with Caddy. |

### Set a partner's pool without tiers

Without the `POLAR_PARTNER_*` products, you can limit the minutes and chats a partner's businesses share each month. Run this from a checkout of the repository, with `DATABASE_URL` pointing at your database:

```bash
pnpm partner-pool:set --partner acme --minutes 500 --chats 2000
```

- **`--partner`**: the partner's ID, its subdomain, such as `acme` or `acme.receptionistportal.com`, or its own verified domain
- **`--minutes`** and **`--chats`**: what the businesses share each month. Leave one out to keep its current limit.
- **`--clear`**: removes both limits

Nothing bills overage without tier products, so the pool is the limit: no overage and no cap. At the pool, the partner's businesses forward calls to each business's transfer number or its owner's verified phone, and their website chat stops replying until the month starts over. The pool applies from the next call or chat. The partner's owners and admins get an email at 80% and at 100% of it, and owners see this month's use on the console's **Billing** page.

While you sell tiers, each partner's tier sets its pool, so the command refuses a limit. It checks the products set in its own shell and the ones the worker last started with.

## Observability

| Variable | Purpose |
| --- | --- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP base URL. LobbyStack appends `/v1/traces`, `/v1/metrics`, and `/v1/logs`. Leave empty to disable export. |
| `OTEL_EXPORTER_OTLP_HEADERS` | Optional comma-separated `key=value` headers sent with each OTLP request. For PostHog, use `Authorization=Bearer your_posthog_project_token_here`. |

An empty OTLP endpoint does not disable container stdout logs, application health endpoints, direct product analytics, or direct error reporting.

## Providers

| Variable group | Purpose |
| --- | --- |
| `TWILIO_*` | Voice, verification, number provisioning, and webhook authentication. |
| `OPENAI_API_KEY` | GPT-Live calls and the fallback key for `AI_CHAT_*` and `AI_EMBEDDING_*`. |
| `AI_CHAT_API_KEY`, `AI_CHAT_BASE_URL`, `AI_CHAT_MODEL`, `AI_CHAT_PROVIDER_NAME` | The receptionist agent for website chat and calls. Leave `AI_CHAT_MODEL` blank on OpenAI to use `gpt-6-luna`. Set it for any other OpenAI-compatible endpoint. |
| `AI_CHAT_REASONING_EFFORT` | OpenAI only: `none`, `minimal`, `low`, `medium`, `high`, or `xhigh`. Defaults to `high`. |
| `AI_SUMMARY_MODEL` | The model the worker uses on the `AI_CHAT_*` endpoint to write the one-line summary of each finished call and pick up the caller's name. Leave it blank to use `AI_CHAT_MODEL`. With a different model, the call summary's AI cost stays unknown, because the `AI_CHAT_*` prices describe the chat model. Without any text model, calls fall back to a summary taken from the transcript. |
| `AI_SUMMARY_REASONING_EFFORT` | OpenAI only: reasoning effort for call summaries. Defaults to `low`. |
| `AI_DELEGATION_MODEL` | The model the worker uses on the `AI_CHAT_*` endpoint to answer what GPT-Live hands off during a call, such as a booking or a message. The caller hears silence until it answers. Leave it blank to use `AI_CHAT_MODEL`. With a different model, the `AI_CHAT_*` prices don't apply. |
| `AI_DELEGATION_REASONING_EFFORT` | OpenAI only: reasoning effort for answers during calls. Defaults to `low`, which answers in about half the time of `high`. Website chat keeps `AI_CHAT_REASONING_EFFORT`. |
| `AI_DELEGATION_SERVICE_TIER` | OpenAI only: the processing tier for answers during calls: `auto`, `default`, `flex` or `priority`. Defaults to `priority`, which answers faster and costs twice the standard token price. |
| `AI_CHAT_INPUT_COST_PER_MILLION_TOKENS`, `AI_CHAT_CACHED_INPUT_COST_PER_MILLION_TOKENS`, `AI_CHAT_OUTPUT_COST_PER_MILLION_TOKENS` | The `AI_CHAT_*` model's prices in USD per million tokens, so chat, call summaries and answers during calls record what they cost. Cached input uses the input price when you leave it blank. |
| `AI_CHAT_PRICING_VERSION`, `AI_CHAT_PRICING_SOURCE`, `AI_CHAT_PRICING_EFFECTIVE_DATE` | A label, a source URL and the date for those prices. LobbyStack records a cost only when all three are set. |
| `AI_EMBEDDING_API_KEY`, `AI_EMBEDDING_BASE_URL`, `AI_EMBEDDING_MODEL`, `AI_EMBEDDING_PROVIDER_NAME`, `AI_EMBEDDING_REVISION` | OpenAI-compatible 1536-dimensional embeddings. |
| `WIDGET_SESSION_SECRET` | Signs cross-origin website-widget sessions. |
| `FIRECRAWL_*` | Website knowledge ingestion. |
| `GOOGLE_*` | Google Calendar OAuth and **Continue with Google** sign-in. |
| `INSTAGRAM_*` | Instagram direct messages: `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET` and `INSTAGRAM_REDIRECT_URI` from a Meta app with Instagram Business Login, and `INSTAGRAM_WEBHOOK_VERIFY_TOKEN` for the `/api/webhooks/instagram` subscription. |
| `SMTP_*`, `EMAIL_*` | Transactional email. |
| `POLAR_*` | Hosted billing and usage meters. |
| `POSTHOG_*` | Direct product analytics and error reporting. |

<Warning>
  Never place secrets in `NEXT_PUBLIC_*` variables. Next.js includes those values in browser bundles.
</Warning>
