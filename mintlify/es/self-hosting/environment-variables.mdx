Use `.env.example` como fuente de referencia. Guarde los valores de producción en el gestor de secretos de su implementación o en un archivo `.env` con permisos restringidos.

## Aplicación y base de datos

| Variable | Función |
| --- | --- |
| `APP_BASE_URL` | URL HTTPS pública del panel y de la API. |
| `DEPLOYMENT_MODE` | `cloud`, `self_hosted_standard` o `development`. |
| `DATABASE_URL` | Conexión a PostgreSQL para el rol principal del servicio: `lobbystack_app` para el servicio de administración, `lobbystack_worker` para el worker. |
| `LOBBYSTACK_AUTH_PASSWORD`, `LOBBYSTACK_WORKER_PASSWORD`, `LOBBYSTACK_DISPATCHER_PASSWORD` | Contraseñas de los demás roles. Un servicio se conecta con cada rol combinando el host y la base de datos de `DATABASE_URL` con la contraseña de ese rol. |
| `LOBBYSTACK_<ROLE>_DATABASE_URL` | Opcional. Reemplaza la cadena de conexión construida para un rol, por ejemplo para usar otro host. |
| `BETTER_AUTH_SECRET` | Secreto de firma de Better Auth. Use al menos 32 caracteres aleatorios. |
| `ENCRYPTION_KEY` | Cifra las credenciales de la aplicación almacenadas. |
| `OTP_HASH_SECRET` | Genera el hash de los códigos de verificación de un solo uso y de los PIN de quienes llaman. Configure el mismo valor en el servicio de administración y en el worker. Si lo cambia, todos los PIN guardados dejan de funcionar. |

## Imagen de marca

Configúrelas en el servicio de administración. Cada una tiene prioridad sobre el nombre y el logo que elige el primer propietario de la implementación durante la incorporación, así que déjelas vacías para que esa persona elija. Páselas también a la compilación del servicio de administración, como argumentos de compilación de Docker con el mismo nombre, para que las páginas de inicio de sesión prerrenderizadas las muestren sin consultar antes al servidor.

| Variable | Función |
| --- | --- |
| `BRAND_APP_NAME` | El nombre que muestra el panel en lugar de LobbyStack, de hasta 40 caracteres. Aparece en la pestaña del navegador, encima de las páginas de inicio de sesión y de incorporación, y en los textos del panel. |
| `BRAND_LOGO_URL` | El logo que aparece junto al nombre y como icono de la pestaña. Use una URL `https://` o una ruta del panel, como `/brand/logo.svg`. Sin logo, una implementación con otro nombre muestra solo su nombre. |

Los enlaces del panel a páginas externas vienen de cinco variables más. Next.js las escribe en la compilación del servicio de administración, así que páselas como argumentos de compilación de Docker con el mismo nombre y vuelva a compilar después de cambiar una. Deje una vacía o sin configurar para enlazar a la página de LobbyStack.

| Variable | Función |
| --- | --- |
| `NEXT_PUBLIC_LANDING_SITE_URL` | Su sitio web, como `https://example.com`. La página de demostración pública enlaza a él, y la respuesta SMS a HELP lo indica. Sin sus propias variables, los enlaces a los términos y a la privacidad abren `/terms` y `/privacy` en ese sitio. |
| `NEXT_PUBLIC_TERMS_URL` | Sus términos del servicio, enlazados debajo del formulario de registro, al pie de la incorporación y desde el programa de afiliados. |
| `NEXT_PUBLIC_PRIVACY_URL` | Su política de privacidad, enlazada debajo del formulario de registro y al pie de la incorporación. |
| `NEXT_PUBLIC_DOCS_SITE_URL` | Su documentación, enlazada desde el panel Comentarios y desde los metadatos del servidor MCP. |
| `NEXT_PUBLIC_CONTACT_EMAIL` | La única dirección a la que se le escribe: el enlace de contacto del panel Comentarios, el botón de contacto del plan Enterprise y las respuestas SMS a HELP. |

La respuesta SMS a HELP empieza con el nombre de la aplicación. Los correos electrónicos, la API y los demás SMS todavía dicen LobbyStack.

## Servicios internos

| Variable | Función |
| --- | --- |
| `INTERNAL_SERVICE_SECRET` | Firma los tokens de fin de llamada del navegador y otros valores internos de corta duración. |
| `INTERNAL_SERVICE_TOKEN` | Autentica el traspaso de llamadas del servicio de administración al worker y las rutas internas de estado protegidas. Configure el mismo valor en el servicio de administración y en el worker. |
| `WORKER_INTERNAL_URL` | URL privada del puerto HTTP del worker, que el servicio de administración usa para pasarle cada llamada. Compose la configura como `http://worker:3002`. |

## Llamadas de voz

El modelo GPT-Live de OpenAI contesta las llamadas desde el navegador y las llamadas telefónicas. Las llamadas telefónicas le llegan a través de su trunk SIP de Twilio. El servicio de administración inicia cada llamada y el worker la ejecuta.

| Variable | Función |
| --- | --- |
| `LIVE_PROTOTYPE_ENABLED` | Configúrela como `true` en el servicio de administración y en el worker. Compose la configura por defecto. Sin ella, las llamadas desde el navegador fallan. |
| `OPENAI_WEBHOOK_SECRET` | Verifica el webhook de llamadas entrantes de OpenAI en `/api/webhooks/openai/live`. Solo para llamadas telefónicas. |
| `TWILIO_SIP_TRUNK_SID` | El trunk Elastic SIP de Twilio que envía las llamadas a su proyecto de OpenAI. Los números nuevos se agregan a él, y el worker no aprovisiona un número sin esta variable. |
| `WEB_CALL_MAX_DURATION_MS` | Límite opcional de la duración de las llamadas desde el navegador. |
| `WEB_CALL_PUBLIC_BUSINESS_SLUG` | Negocio que contesta la llamada de demostración pública en su sitio de marketing. |
| `WEB_CALL_ALLOWED_ORIGINS` | Sitios, separados por comas, autorizados a iniciar esa llamada de demostración pública. Las llamadas del widget del sitio web usan en su lugar los orígenes permitidos de cada clave de widget. |

## Redis y almacenamiento de archivos

| Variable | Función |
| --- | --- |
| `REDIS_URL` | URL de conexión a Redis que usan los entornos de ejecución del servicio de administración y del worker. |
| `STORAGE_PROVIDER` | `local` por defecto. Configúrela como `s3` para AWS S3, MinIO u otro servicio compatible. |
| `LOCAL_STORAGE_PATH` | Ruta del sistema de archivos compartida por el servicio de administración y el worker. Compose monta su volumen persistente en `/var/lib/lobbystack/storage`. |
| `LOCAL_STORAGE_SIGNING_SECRET` | Firma las URL locales de subida y descarga de corta duración. Use un valor aleatorio largo. Fuera de Compose, usa `INTERNAL_SERVICE_SECRET` si no está definida. |
| `S3_ENDPOINT` | Endpoint opcional compatible con S3. Déjela vacía para AWS S3. |
| `S3_BUCKET` | Bucket para las grabaciones y los archivos subidos. |
| `S3_REGION` | Región de S3. El valor predeterminado es `us-east-1`. |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Credenciales del almacenamiento de objetos. |
| `S3_FORCE_PATH_STYLE` | Configúrela como `true` para MinIO. |

El almacenamiento local sirve para una implementación en un solo host. Use S3 cuando el servicio de administración y el worker se ejecuten en hosts distintos o cuando necesite un almacenamiento gestionado fuera del host de Docker.

## API pública y webhooks

| Variable | Función |
| --- | --- |
| `PUBLIC_API_RATE_LIMIT_PER_MINUTE` | Solicitudes por minuto para cada clave de API en `/api/v1`. El valor predeterminado es `120`. Configúrela en el servicio de administración. El límite usa `REDIS_URL`; en producción, las solicitudes fallan con `503` cuando no se puede acceder a Redis. |
| `PLATFORM_API_KEYS` | Claves de plataforma (`lsp_...`) que registran y administran negocios en `/api/v1`, como un arreglo JSON. Cada entrada indica su grupo (`group`), la cuenta verificada en cuyo nombre actúa (`owner_email`) y si llega a todos los negocios (`"access": "all"`) o solo a los que registraron las claves de su grupo (`"access": "group"`). Las entradas más antiguas indican el grupo en `partner`, que sigue funcionando. `pnpm platform-key:create` crea una clave e imprime su entrada; la entrada solo guarda un hash de la clave. Una clave con `"access": "all"` y su cuenta propietaria son credenciales raíz: llegan a todos los negocios. Configúrela en el servicio de administración. Déjela vacía si no hay ninguna. Las claves que los socios crean en su consola se guardan en la base de datos. |
| `ENCRYPTION_KEY` | También cifra los secretos de firma de los webhooks y sirve de clave para el HMAC con el que se almacenan los hashes de las claves de API. Configure el mismo valor en el servicio de administración y en el worker, o el worker no podrá firmar las entregas. Cambiarla invalida todas las claves de API y todos los secretos de webhook. |

Las entregas de webhooks rechazan las direcciones privadas, de loopback, de enlace local y de metadatos de la nube en todas las implementaciones, incluidas las autoalojadas. Apunte los endpoints a una URL HTTPS pública. Las URL `http://` simples solo funcionan cuando `NODE_ENV=development`.

## Socios

Los socios revenden su despliegue a los negocios que atienden, con su propia marca. Se registran y gestionan su equipo desde la consola de socios, en `/partner` de su panel. Defina estas variables en el admin y en el worker.

| Variable | Función |
| --- | --- |
| `PARTNER_SIGNUP` | Quién puede registrarse como socio en `/partner/signup`: `open` permite registrarse a cualquier persona, e `invite` exige un enlace de registro. `pnpm partner-invite:create --email owner@acme.example` escribe un enlace que funciona una vez, para ese correo verificado, durante 7 días. El valor predeterminado es `open`, salvo cuando `DEPLOYMENT_MODE` es `cloud` y la facturación de niveles de socios está desactivada: entonces es `invite`, para que ningún socio se registre antes de poder comprar un nivel. La facturación de niveles se activa cuando todos los `POLAR_PARTNER_*_PRODUCT_ID` están definidos. |
| `PARTNER_BASE_DOMAIN` | El dominio del que sus socios reciben subdominios, como `receptionistportal.com`. El registro reserva uno para cada socio nuevo, como `acme.receptionistportal.com`, y el admin reserva uno al iniciarse para cada socio que se registró antes de que usted la definiera. En esos subdominios, las personas se registran e inician sesión con la marca del socio, con correo y contraseña. Los correos propios de un socio, como las invitaciones a su equipo, salen con su nombre desde `no-reply@` ese dominio, así que su proveedor de correo debe aceptar ese remitente. Sin esta variable, los correos de un socio salen desde la dirección de `EMAIL_FROM`. Las respuestas llegan al correo de soporte que el socio define en su página **Marca y dominio**. |
| `STRIPE_CONNECT_SECRET_KEY` | Una clave secreta (`sk_...`) o una clave restringida (`rk_...`) de su cuenta de plataforma de Stripe, con acceso de escritura a las cuentas de Connect, los productos, los precios, las sesiones de Checkout, las sesiones del portal de clientes, las suscripciones, los elementos de suscripción, los medidores de facturación y sus eventos. Active primero Connect en su cuenta de Stripe, y defina las dos variables de Stripe Connect en el admin y en el worker. Con `STRIPE_CONNECT_WEBHOOK_SECRET`, esta clave activa Stripe Connect. El propietario de cada socio conecta entonces la cuenta de Stripe del socio en la página **Pagos** de la consola. Los propietarios y administradores venden paquetes en la página **Paquetes** y eligen el paquete de cada negocio en la página **Negocios**. Ahí también pueden activar el excedente de un negocio, con un precio por cada minuto y cada chat de más y un límite mensual opcional, en la moneda del paquete. El negocio sigue respondiendo pasados los minutos y chats de su paquete hasta que su excedente llega al límite. Con el excedente desactivado o al llegar al límite, sus llamadas se desvían y el chat de su sitio deja de responder. El worker envía el excedente de cada negocio a la cuenta de Stripe del socio como eventos de medidor, uno por llamada o chat, y agrega los precios Call overage y Chat overage a la suscripción del negocio la primera vez que tiene excedente, para que aparezca en su próxima factura. Los propietarios y administradores del negocio reciben un correo a nombre del socio al 80 % y al 100 % de los minutos y de los chats de su paquete. El propietario del negocio paga en un Stripe Checkout en la cuenta del socio, que abre el enlace de la invitación. Después, abre el portal de clientes del socio desde **Configuración → Facturación**, así que cada socio guarda la configuración de su portal de clientes en su propio panel de Stripe. Noventa días después de que termina el nivel de un socio, el worker elimina sus negocios y antes cancela la suscripción al paquete de cada uno, para que su propietario no pague nada más. Sin ambas variables, los socios facturan cada negocio fuera de LobbyStack. |
| `STRIPE_CONNECT_WEBHOOK_SECRET` | El secreto de firma (`whsec_...`) del endpoint de webhook en `APP_BASE_URL` + `/api/webhooks/stripe`. En Stripe, cree el endpoint para los eventos de las cuentas conectadas y envíele `account.updated`, `account.application.deauthorized`, `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `customer.subscription.paused`, `customer.subscription.resumed`, `invoice.paid` y `invoice.payment_failed`. Así la consola muestra cuándo la cuenta de un socio puede aceptar pagos y cuándo el socio la desconecta. Un negocio con un paquete recibe sus minutos y chats mientras su suscripción paga, incluso con un pago atrasado. |
| `POLAR_PARTNER_STARTER_MONTHLY_PRODUCT_ID`, `POLAR_PARTNER_STARTER_ANNUAL_PRODUCT_ID`, `POLAR_PARTNER_GROWTH_MONTHLY_PRODUCT_ID`, `POLAR_PARTNER_GROWTH_ANNUAL_PRODUCT_ID`, `POLAR_PARTNER_SCALE_MONTHLY_PRODUCT_ID`, `POLAR_PARTNER_SCALE_ANNUAL_PRODUCT_ID` | Los productos de Polar con los que vende los niveles de socio: Starter, Growth y Scale, mensuales y anuales. Cuando los seis están definidos, cada uno con su propio producto, los propietarios de un socio compran un nivel desde la página **Facturación** de la consola y pagan en un pago de Polar. Después, los webhooks de Polar fijan el nivel del socio con el mismo `POLAR_WEBHOOK_SECRET` que sus planes. Un socio que no paga ningún nivel está en Gratis. Cuando el nivel de pago de un socio termina o falla un pago, sus negocios siguen atendiendo durante 30 días. Después se pausan y sus llamadas se desvían, y 90 días después de que terminó el nivel, el worker los elimina y libera sus números de teléfono. Un nivel también fija cuántos números de teléfono tienen los negocios del socio, y cada número adicional le cuesta al socio lo que Twilio le cobra a usted por él. El nivel también fija la bolsa de minutos y chats que los negocios del socio comparten cada mes. Pasada la bolsa, siguen respondiendo, y el worker envía el excedente a Polar como eventos `billing.partner_pool_voice_overage` y `billing.partner_pool_chat_overage`, hasta el límite mensual que fijan los propietarios del socio. Los propietarios y los administradores del socio reciben un correo al 80 % y al 100 % de la bolsa y del límite. Gratis no tiene excedente. Déjelos vacíos y los socios no le pagan ningún nivel. Nada limita entonces los números de teléfono de sus negocios, ni sus minutos y chats, salvo que fije la bolsa de un socio como describe la sección siguiente. La página **Facturación** muestra los precios de la nube, así que use los mismos en sus productos. También necesitan `POLAR_ACCESS_TOKEN` y `POLAR_ORGANIZATION_ID`. |
| `CADDY_ON_DEMAND_TLS` | Póngalo en `true` cuando el Caddy de Compose sirva HTTPS con `docker-compose.tls.yml`. Los socios pueden entonces conectar un subdominio de su propio sitio web, como `app.acmeagency.com`, en la página **Marca y dominio** de la consola. Mientras venda niveles de socio con los productos `POLAR_PARTNER_*`, un socio necesita un nivel de pago para hacerlo; si no, cualquier socio puede. El worker comprueba cada pocos minutos que el DNS del dominio llegue a `PARTNER_DOMAIN_CNAME_TARGET` y contenga el registro TXT del socio, y el dominio se activa en cuanto llega. Caddy emite su certificado en la primera visita, después de que `/api/tls/ask` lo apruebe. El valor predeterminado es `false`. |
| `CLOUDFLARE_SAAS_API_TOKEN` | Un token de API de Cloudflare con permiso para editar los nombres de host personalizados de la zona de `CLOUDFLARE_SAAS_ZONE_ID`. Con ambas variables, los socios conectan sus propios dominios mediante Cloudflare for SaaS en lugar de Caddy: el worker registra cada dominio como nombre de host personalizado, y el dominio se activa cuando Cloudflare informa que el nombre de host y su certificado están activos. |
| `CLOUDFLARE_SAAS_ZONE_ID` | El ID de la zona de Cloudflare que contiene sus nombres de host personalizados, normalmente la zona de `PARTNER_BASE_DOMAIN`. Dé a la zona un origen de respaldo que llegue a su admin. |
| `PARTNER_DOMAIN_CNAME_TARGET` | El nombre de host al que los socios apuntan el registro CNAME de su dominio. Si no lo define, es el origen de respaldo de la zona con Cloudflare for SaaS, y el nombre de host de `APP_BASE_URL` con Caddy. |

### Fijar la bolsa de un socio sin niveles

Sin los productos `POLAR_PARTNER_*`, puede limitar los minutos y los chats que los negocios de un socio comparten cada mes. Ejecute este comando desde una copia del repositorio, con `DATABASE_URL` apuntando a su base de datos:

```bash
pnpm partner-pool:set --partner acme --minutes 500 --chats 2000
```

- **`--partner`**: el ID del socio, su subdominio, como `acme` o `acme.receptionistportal.com`, o su propio dominio verificado
- **`--minutes`** y **`--chats`**: lo que los negocios comparten cada mes. Omita uno para mantener su límite actual.
- **`--clear`**: quita ambos límites

Sin productos de nivel, nada cobra excedente, así que la bolsa es el límite: sin excedente ni límite de gasto. Cuando se agota la bolsa, los negocios del socio desvían sus llamadas al número de transferencia de cada negocio o al teléfono verificado de su propietario, y el chat de su sitio deja de responder hasta que empieza el mes siguiente. La bolsa se aplica desde la siguiente llamada o chat. Los propietarios y los administradores del socio reciben un correo al 80 % y al 100 % de la bolsa, y los propietarios ven el uso del mes en la página **Facturación** de la consola.

Mientras venda niveles, el nivel de cada socio fija su bolsa, así que el comando rechaza un límite. Revisa los productos definidos en su propio shell y los que tenía el worker la última vez que se inició.

## Observabilidad

| Variable | Función |
| --- | --- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | URL base de OTLP. LobbyStack agrega `/v1/traces`, `/v1/metrics` y `/v1/logs`. Déjela vacía para desactivar la exportación. |
| `OTEL_EXPORTER_OTLP_HEADERS` | Encabezados `key=value` opcionales, separados por comas, que se envían con cada solicitud OTLP. Para PostHog, use `Authorization=Bearer your_posthog_project_token_here`. |

Un endpoint OTLP vacío no desactiva los registros stdout de los contenedores, los endpoints de estado de la aplicación, las analíticas de producto directas ni el reporte de errores directo.

## Proveedores

| Grupo de variables | Función |
| --- | --- |
| `TWILIO_*` | Voz, verificación, aprovisionamiento de números y autenticación de webhooks. |
| `OPENAI_API_KEY` | Llamadas de GPT-Live y clave de respaldo para `AI_CHAT_*` y `AI_EMBEDDING_*`. |
| `AI_CHAT_API_KEY`, `AI_CHAT_BASE_URL`, `AI_CHAT_MODEL`, `AI_CHAT_PROVIDER_NAME` | El agente de la recepcionista para el chat del sitio web y las llamadas. Deje `AI_CHAT_MODEL` en blanco con OpenAI para usar `gpt-6-luna`. Configúrela para cualquier otro endpoint compatible con OpenAI. |
| `AI_CHAT_REASONING_EFFORT` | Solo OpenAI: `none`, `minimal`, `low`, `medium`, `high` o `xhigh`. El valor predeterminado es `high`. |
| `AI_SUMMARY_MODEL` | El modelo que el worker usa en el endpoint `AI_CHAT_*` para escribir el resumen de una línea de cada llamada terminada y obtener el nombre de la persona que llama. Déjela en blanco para usar `AI_CHAT_MODEL`. Con un modelo distinto, el costo de IA del resumen de la llamada queda desconocido, porque los precios de `AI_CHAT_*` corresponden al modelo de chat. Sin ningún modelo de texto, las llamadas recurren a un resumen tomado de la transcripción. |
| `AI_SUMMARY_REASONING_EFFORT` | Solo OpenAI: esfuerzo de razonamiento para los resúmenes de llamadas. El valor predeterminado es `low`. |
| `AI_DELEGATION_MODEL` | El modelo que el worker usa en el endpoint `AI_CHAT_*` para responder lo que GPT-Live le delega durante una llamada, como una reserva o un mensaje. La persona que llama no oye nada hasta que responde. Déjela en blanco para usar `AI_CHAT_MODEL`. Con un modelo distinto, los precios de `AI_CHAT_*` no se aplican. |
| `AI_DELEGATION_REASONING_EFFORT` | Solo OpenAI: esfuerzo de razonamiento para las respuestas durante las llamadas. El valor predeterminado es `low`, que responde en cerca de la mitad del tiempo que `high`. El chat del sitio sigue usando `AI_CHAT_REASONING_EFFORT`. |
| `AI_DELEGATION_SERVICE_TIER` | Solo OpenAI: el nivel de procesamiento de las respuestas durante las llamadas: `auto`, `default`, `flex` o `priority`. El valor predeterminado es `priority`, que responde más rápido y cuesta el doble del precio estándar por token. |
| `AI_CHAT_INPUT_COST_PER_MILLION_TOKENS`, `AI_CHAT_CACHED_INPUT_COST_PER_MILLION_TOKENS`, `AI_CHAT_OUTPUT_COST_PER_MILLION_TOKENS` | Los precios del modelo `AI_CHAT_*` en dólares estadounidenses por millón de tokens, para que el chat, los resúmenes de llamadas y las respuestas durante las llamadas registren su costo. La entrada en caché usa el precio de entrada si la dejas vacía. |
| `AI_CHAT_PRICING_VERSION`, `AI_CHAT_PRICING_SOURCE`, `AI_CHAT_PRICING_EFFECTIVE_DATE` | Una etiqueta, una URL de origen y la fecha de esos precios. LobbyStack registra un costo solo si las tres están definidas. |
| `AI_EMBEDDING_API_KEY`, `AI_EMBEDDING_BASE_URL`, `AI_EMBEDDING_MODEL`, `AI_EMBEDDING_PROVIDER_NAME`, `AI_EMBEDDING_REVISION` | Embeddings de 1536 dimensiones compatibles con OpenAI. |
| `WIDGET_SESSION_SECRET` | Firma las sesiones de origen cruzado del widget del sitio web. |
| `FIRECRAWL_*` | Importación de conocimiento desde el sitio web. |
| `GOOGLE_*` | OAuth de Google Calendar e inicio de sesión con **Continuar con Google**. |
| `INSTAGRAM_*` | Mensajes directos de Instagram: `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET` e `INSTAGRAM_REDIRECT_URI` de una aplicación de Meta con Instagram Business Login, e `INSTAGRAM_WEBHOOK_VERIFY_TOKEN` para la suscripción de `/api/webhooks/instagram`. |
| `SMTP_*`, `EMAIL_*` | Correo electrónico transaccional. |
| `POLAR_*` | Facturación alojada y medidores de uso. |
| `POSTHOG_*` | Analíticas de producto directas y reporte de errores. |

<Warning>
  Nunca ponga secretos en variables `NEXT_PUBLIC_*`. Next.js incluye esos valores en los paquetes del navegador.
</Warning>
