La base Docker Compose exécute l'application LobbyStack, PostgreSQL, Redis et un volume de stockage local partagé. Connectez vos propres comptes fournisseurs pour les fonctionnalités externes.

## Requis pour les appels en direct

<AccordionGroup>
  <Accordion title="Twilio" icon="phone">
    Twilio fournit les numéros de téléphone, les transferts d'appel et la vérification des numéros de téléphone. Un trunk Elastic SIP envoie à OpenAI les appels reçus sur vos numéros. Chaque numéro doit faire partie du trunk pour répondre aux appels. Gardez le jeton d'authentification Twilio côté serveur.
  </Accordion>
  <Accordion title="Telnyx" icon="phone">
    Telnyx peut remplacer Twilio pour certains pays ou certaines fonctions, ou pour tout. Le worker donne à chaque numéro Telnyx sa propre connexion FQDN vers OpenAI, un profil de messagerie gère les textos, et une application TeXML prend les appels auxquels la réceptionniste cesse de répondre. Réglez `TELEPHONY_NUMBERS` pour choisir les pays dont vous achetez les numéros chez Telnyx, et `TELEPHONY_VERIFY` ou `TELEPHONY_LOOKUP` pour utiliser Telnyx Verify ou Number Lookup. Donnez à l'application TeXML le même profil vocal sortant que `TELNYX_OUTBOUND_VOICE_PROFILE_ID`, sinon les appels transférés coupent après une seconde. Utilisez un numéro d'un autre opérateur comme numéro de transfert, car les appels entre numéros Telnyx n'atteignent pas la réceptionniste. Si un transfert échoue avec une erreur 603, demandez au soutien de Telnyx d'activer SIP REFER sur votre compte. Gardez la clé d'API côté serveur.
  </Accordion>
  <Accordion title="OpenAI" icon="waveform">
    Le modèle GPT-Live d'OpenAI mène la conversation pendant les appels téléphoniques et les appels dans le navigateur, et OpenAI héberge l'audio. Quand l'appelant a besoin de données de l'entreprise, comme des disponibilités ou une réservation, GPT-Live interroge le worker de LobbyStack, qui répond avec l'agent réceptionniste. Votre projet OpenAI doit avoir SIP activé et un webhook d'appel entrant pour les appels téléphoniques.
  </Accordion>
</AccordionGroup>

## Connaissances et automatisation

<AccordionGroup>
  <Accordion title="IA compatible OpenAI" icon="sparkles">
    L'agent réceptionniste pour le clavardage du site Web et les appels utilise par défaut `gpt-6-luna` avec un raisonnement élevé. Pour utiliser un autre fournisseur ou un environnement d'exécution auto-hébergé qui implémente les API de clavardage et d'embeddings compatibles OpenAI, définissez les variables `AI_CHAT_*` et `AI_EMBEDDING_*`. Le modèle doit prendre en charge les appels d'outils, et les modèles d'embeddings doivent renvoyer exactement 1536 dimensions.
  </Accordion>
  <Accordion title="Firecrawl" icon="globe">
    Firecrawl importe le contenu public des sites Web dans le pipeline de connaissances. Vous pouvez vous en passer si les opérateurs se contentent de téléverser des documents et de saisir les connaissances à la main.
  </Accordion>
</AccordionGroup>

## Intégrations facultatives

- Google Calendar pour les disponibilités et la synchronisation des réservations
- SMTP pour la vérification, la réinitialisation des mots de passe et les courriels opérationnels
- Polar pour la facturation hébergée et l'utilisation mesurée
- PostHog et OpenTelemetry pour l'analytique, le suivi des erreurs, les traces, les métriques et les journaux
- AWS S3 ou un stockage compatible pour les déploiements sur plusieurs hôtes
- MinIO par le profil Compose facultatif `minio`
- PostgreSQL et Redis gérés à la place des conteneurs inclus

Définissez `STORAGE_PROVIDER=s3` pour AWS S3, MinIO ou un autre service compatible. Laissez `S3_ENDPOINT` vide pour AWS S3. MinIO exige son point de terminaison HTTP et `S3_FORCE_PATH_STYLE=true`.

Consultez la [référence des variables d'environnement](/fr/self-hosting/environment-variables) pour les noms de configuration et le [guide Docker Compose](/fr/self-hosting/docker-compose) pour les étapes de déploiement.
